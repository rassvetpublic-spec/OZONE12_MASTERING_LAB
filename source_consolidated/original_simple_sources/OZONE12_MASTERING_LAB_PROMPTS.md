# OZONE12_MASTERING_LAB_PROMPTS

Библиотека из 30 рабочих промптов для проекта **OZONE12_MASTERING_LAB**.

Фокус проекта: готовый SUNO stereo WAV → **iZotope Ozone 12 Advanced** → WAV 24-bit / 48 kHz для площадок. DAW используется только как render-host; основной хост пользователя — REAPER, Ableton допускается как контейнер. Первый этап проекта: без GUI-автоматизации Ableton; приоритет — XML-вилки пресетов, WAV-анализ, Markdown/CSV-отчёты.

---

## Проверенные источники и выводы

### Что учтено

1. Project Instructions текущего проекта.
2. Загруженный источник `Ozone12_only_mastering_project_strategy.md`.
3. История проектных чатов по Ozone 12 / SUNO WAV / XML-пресетам.
4. Доступный персональный контекст по предыдущим задачам проекта.
5. Проверка доступного GitHub connector.

### Что подтверждено

- Ozone 12 Advanced рассматривается как единственный мастеринг-процессор.
- REAPER/Ableton — только render-host, без звуковой обработки до/после Ozone.
- Активную цепь Ozone нужно определять по `ElementChain`, а не по `Enabled=1`.
- Порядок модулей критичен: он влияет на фазу, динамику, ширину, резкость и громкость.
- Без отдельного теста не включать: `Stereoize`, `Soft Clip`, Recover Sides выше +1.2 dB, очень громкие цели около −8.5 LUFS, Waves до/после Ozone, дополнительный лимитер после Ozone, Normalize при экспорте.
- Целевой профиль для dark gothic / industrial streaming: примерно −12.3…−11.5 LUFS Integrated, True Peak около −2.0 dBTP, WAV 24-bit / 48 kHz.
- Повторяющиеся задачи проекта: проверка источников, разбор XML, декодирование `ElementChain`, генерация вилок, анализ WAV, сравнение метрик, выбор кандидата, аудит MP3/стриминговой устойчивости, отчёты.

### Ограничения проверки

- Связанный GitHub-репозиторий по запросам `OZONE12_MASTERING_LAB`, `Ozone mastering`, `SUNO REAPER` в доступных установленных репозиториях не найден. Поэтому GitHub-часть учтена как пустой источник, без выдумывания репозитория.
- Локально в `/mnt/data` найден только `Ozone12_only_mastering_project_strategy.md`.

## Как пользоваться библиотекой

Для каждой повторяющейся задачи есть три варианта:

- **Базовый промпт** — быстрое выполнение типовой операции.
- **Продвинутый промпт** — строгий режим с проверками, рисками и отчётами.
- **Промпт аудита** — проверка результата после выполнения.

Вставляй промпт в новый чат проекта вместе с файлами задачи. Если файлов нет — промпт заставляет сначала составить реестр источников и явно назвать недостающие элементы.
