# OZONE12 XML Structure — Current Working Notes

Проект: **OZONE12_MASTERING_LAB**  
Дата фиксации: 2026-06-30  
Статус: **рабочее описание, подтверждено на текущих пресетах DirtyVibe**

---

## 1. Назначение файла

Этот файл фиксирует текущие рабочие правила по структуре XML-пресетов **iZotope Ozone 12 Advanced** для проекта OZONE12_MASTERING_LAB.

Цель: не ломать пресеты при генерации XML-вилок и не повторять ошибки с пустой цепью модулей в Ozone.

Основной workflow проекта:

```text
SUNO MP3/WAV → Ozone 12 Advanced → WAV 24-bit / 48 kHz
```

DAW используется только как render-host. В текущем прогоне используется Ableton Live 12.

---

## 2. Главное правило

В Ozone 12 нельзя считать активную цепь модулей по `Enabled="1"`.

Правильный источник порядка модулей:

```text
Global / ExtraBytes ElementID="ElementChain"
```

Именно `ElementChain` определяет, какие модули видны в верхней цепи Ozone и в каком порядке они идут.

---

## 3. Структура `ElementChain`

`ElementChain` хранится как Base64-строка в атрибуте `Data`.

После Base64-декодирования структура текущих проверенных пресетов выглядит так:

```text
[00][uint32 little-endian длина имени][UTF-8 имя модуля]
[00][uint32 little-endian длина имени][UTF-8 имя модуля]
[00][uint32 little-endian длина имени][UTF-8 имя модуля]
...
```

Пример логики:

```text
00 + len("Equalizer") + "Equalizer"
00 + len("Impact") + "Impact"
00 + len("Stereo Imager") + "Stereo Imager"
...
```

Важно:

```text
В начале ElementChain НЕТ отдельного счётчика модулей.
```

Ранее была ошибка: был добавлен лишний count-prefix. Это ломало цепь, и Ozone показывал пустой проект.

---

## 4. Проверенные имена модулей в текущем XML

В текущих DirtyVibe-пресетах встречаются следующие имена модулей:

```text
Equalizer
Impact
Stereo Imager
Clarity
Stabilizer
Dynamic EQ
Maximizer
```

Полная auto-цепь исходного пресета:

```text
Equalizer → Impact → Stereo Imager → Clarity → Stabilizer → Dynamic EQ → Maximizer
```

Безопасная логика проекта для финального мастеринга обычно предпочитает:

```text
Equalizer → Impact → Clarity → Stabilizer → Stereo Imager → Dynamic EQ → Maximizer
```

Но порядок модулей нельзя менять вслепую. Ozone может требовать согласованности не только `ElementChain`, но и других внутренних блоков XML.

---

## 5. `Enabled`, `Bypass` и видимая цепь

### 5.1 `Enabled="1"`

`Enabled="1"` в блоке модуля не гарантирует, что модуль находится в видимой цепи Ozone.

Модуль может быть `Enabled="1"`, но отсутствовать в `ElementChain`.

### 5.2 `Bypass`

Попытка делать DIAG-пресеты так:

```text
оставить полную ElementChain
ненужные модули выключить через Bypass
```

оказалась ненадёжной для текущих XML.

Ozone не всегда корректно применял такую схему. Поэтому для диагностики она не является основной.

### 5.3 Надёжный способ диагностики

Для диагностических пресетов надёжнее использовать XML-шаблоны, сохранённые вручную из Ozone после удаления лишних модулей.

Проверенные шаблоны:

```text
equal.xml                       → только Equalizer
equal+impact.xml                → Equalizer → Impact
Only_Equal_other_off.xml         → экспериментальный шаблон, не основной
Equal+Impact_other_off.xml       → экспериментальный шаблон, не основной
```

Основная рабочая методика после проверки:

```text
DIAG-пресеты строить на шаблонах, сохранённых из Ozone.
FULL-пресеты строить на исходном полном auto-пресете или другом полном шаблоне, сохранённом из Ozone.
```

## 6. Методика DIAG / FULL

### 6.1 DIAG-пресеты

DIAG нужен для чистого измерения одного участка цепи.

Пример для баса:

```text
01A_bass_safe_EQIMPACT_DIAG
01B_bass_bold_EQIMPACT_DIAG
```

Цепь DIAG:

```text
Equalizer → Impact
```

Назначение:

```text
услышать и измерить басовую правку без Clarity, Stabilizer, Stereo Imager, Dynamic EQ и Maximizer
```

DIAG-рендеры не являются финальными кандидатами.

### 6.2 FULL-пресеты

FULL нужен для проверки той же идеи в реальной мастеринг-цепи.

Пример:

```text
01A_bass_safe_FULL
01B_bass_bold_FULL
```

Цепь FULL:

```text
Equalizer → Impact → Stereo Imager → Clarity → Stabilizer → Dynamic EQ → Maximizer
```

или другой полный порядок, если он проверен и корректно загружается в Ozone.

FULL-рендеры можно сравнивать как кандидаты для следующего этапа.

---

## 7. Важное правило имён

Ozone Preset Manager может кэшировать старые пресеты с теми же именами.

Если ранее был создан сломанный пресет с именем:

```text
01A_bass_safe_FULL
```

то повторный импорт XML с таким же именем может подтянуть старое состояние или конфликтовать с ним.

Правило:

```text
Для новой серии пресетов использовать уникальный суффикс версии.
```

Пример:

```text
01A_bass_safe_FULL_V6
01B_bass_bold_FULL_V6
```

При подозрении на кэш:

```text
1. Удалить старый пресет из Ozone Preset Manager.
2. Закрыть Ozone.
3. Открыть Ozone заново.
4. Импортировать XML с новым уникальным именем.
```

---

## 8. Что уже признано ошибочным

Не использовать старые подходы:

```text
v3 / v3_FIXED — удаление модулей через ручную пересборку ElementChain без шаблона Ozone.
v4_BYPASS     — полная цепь + Bypass лишних модулей как основной DIAG-метод.
v5            — частично рабочая DIAG-логика, но FULL мог конфликтовать по именам.
```

Рабочий подход:

```text
v6_UNIQUE + template-based DIAG/FULL + уникальные имена пресетов
```

## 9. Алгоритм генерации новых пресетов

### 9.1 Для DIAG

1. Взять проверенный XML-шаблон, сохранённый из Ozone:

```text
equal.xml
или
equal+impact.xml
```

2. Менять только параметры существующих модулей.
3. Не добавлять модули вручную.
4. Не расширять `ElementChain` вручную, если есть шаблон из Ozone.
5. Сохранить пресет с уникальным именем.
6. Проверить в Ozone визуально: нужные модули должны отображаться.

### 9.2 Для FULL

1. Взять полный проверенный XML-шаблон, сохранённый из Ozone:

```text
DirtyVibe_auto.xml
или другой полный рабочий FULL-шаблон
```

2. Менять параметры модулей.
3. Не ломать `ElementChain`.
4. Не использовать старые конфликтные имена.
5. Сохранить с уникальным суффиксом версии.
6. Проверить в Ozone визуально: полная цепь должна отображаться.

## 10. Проверочный чеклист перед рендером

Перед рендером каждого XML:

```text
1. Открыть пресет в Ozone.
2. Проверить, что нужные модули видны сверху.
3. Проверить, что цепь не пустая.
4. Проверить, что имя пресета уникальное.
5. Проверить, что нет лишнего Ableton FX до/после Ozone.
6. Export: WAV / 48 kHz / 24-bit / Normalize Off.
```

Для DIAG:

```text
цепь должна соответствовать диагностическому шаблону
```

Для FULL:

```text
цепь должна быть полной
```

## 11. Текущий план прогонов DirtyVibe

Принятый план:

```text
Bass → Width → Clean/Harshness → Limiter → Final Candidate
```

Каждый этап желательно делать A/B-парами.

Для Bass Stage:

```text
01A_bass_safe_EQIMPACT_DIAG_V6.wav
01B_bass_bold_EQIMPACT_DIAG_V6.wav
01A_bass_safe_FULL_V6.wav
01B_bass_bold_FULL_V6.wav
```

Логика оценки:

```text
DIAG показывает чистое действие EQ/Impact.
FULL показывает, выживает ли эта правка в полной мастеринг-цепи.
```

## 12. Запреты проекта для Ozone-only mastering

Без отдельного теста не включать:

```text
Stereoize
Soft Clip
Recover Sides выше +1.2 dB
цели около -8.5 LUFS
Waves до/после Ozone
дополнительный limiter после Ozone
Normalize при экспорте
```

Для MP3-исходника особенно важно:

```text
не давить слишком громко
не поднимать aggressively air/high shelf
не разгонять True Peak выше безопасного потолка
```

Цель релизного файла:

```text
WAV 24-bit / 48 kHz
примерно -12.0...-11.5 LUFS Integrated
True Peak около -2.0 dBTP
```

---

## 13. Короткая формула для будущих чатов

Если нужно генерировать Ozone XML-вилки:

```text
Не работай по Enabled=1.
Активную цепь читать через Global/ExtraBytes ElementID="ElementChain".
ElementChain — Base64: 00 + uint32 little-endian длина имени + UTF-8 имя модуля, повтор по модулям; без count-prefix.
Для DIAG использовать Ozone-сохранённые шаблоны equal.xml / equal+impact.xml, а не ручное удаление модулей.
Для FULL использовать полный рабочий шаблон и уникальные имена V-серии, чтобы избежать кэша Preset Manager.
Перед рендером обязательно визуально проверить, что Ozone показывает нужную цепь.
```
